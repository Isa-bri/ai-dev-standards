# React Native / Expo — platform traps

These are non-obvious facts about the Expo/React Native platform that have
burned real projects. Copy this into a project's `docs/` and link it from
`CLAUDE.md` under "Traps this project has already learned about."

Each item compiled, passed lint, and only failed on device, in a production
build, or under a specific platform version. None of them are obvious from
reading the code.

---

## Environment variables

**Metro only inlines `process.env.X` when the variable name is a string
literal.** `env[variableName]` compiles and passes lint; it arrives as
`undefined` on device. Always use the literal name at the call site, or use
a centralized env module that does the literal reads.

## URL polyfill

**React Native's `URL` is a partial polyfill — `searchParams` is missing.**
Code that constructs a `URL` and accesses `.searchParams` compiles, passes
the type checker, and only throws on device. Don't use `URL` for query-string
parsing in React Native code; use a purpose-built parser.

## Native build output is generated

**`android/` and `ios/` are generated by `expo prebuild` and must not be
committed or edited directly.** Permissions, icons, and native plugins are
configured in `app.json` and Expo config plugins. Native security hardening
(`usesCleartextTraffic`, `allowBackup`) is set through `expo-build-properties`
for the same reason. Edits to the generated directories don't survive the next
prebuild.

## Date/time picker

**`mode="datetime"` on `@react-native-community/datetimepicker` is iOS-only.**
On Android it crashes the entire component tree (`pickers['datetime']` is
`undefined`, and the module's cleanup call throws on OK and Cancel). The TypeScript
type won't catch it because `mode` is a union of both platforms' modes. On
Android, pick date and time in two separate pickers.

## Image picker quality parameter

**Passing `quality` to `expo-image-picker` on Android 16+ with the new photo
picker crashes or returns no asset.** The re-encoder can't handle the
`content://media/picker/...` URI scheme introduced in Android 16 and throws
`IllegalArgumentException: Uri lacks 'file' scheme`. Omit `quality` entirely;
validate the media type from the file bytes instead.

## On-device development — `adb reverse` is enough

**You don't need a tunnel to connect a physical device to a local dev
server.** `adb reverse tcp:<port> tcp:<port>` (repeat for each port your dev
stack uses) with the local URL in your env file is simpler, more reliable,
and avoids cleartext-traffic issues. The React Native dev client's
`network_security_config` permits cleartext to `localhost` by default. This
exception does not apply to release builds.

## Cold-start navigation

**Navigating on cold start by waiting for the data alone is too early — wait
for the route segment.** If the app's root redirects to a role-specific
segment once the session is ready, a push that arrives during that redirect
lands on a tree that the redirect immediately replaces, and the push silently
disappears. Wait until `useSegments()` (or equivalent) shows that the redirect
has landed, not just that the session exists. `usePathname` doesn't help here
when the target is a route group (both the group index and the root appear as
`/`).

## Babel preset / plugin declared in a workspace root

**A Babel preset or plugin hoisted by pnpm to the workspace root works in
`expo start` but breaks the APK build.** `expo start` runs through `pnpm exec`
which sets `NODE_PATH` to the hoisted directory; Gradle's `node` invocation
does not. Declare every Babel dependency in the `apps/mobile/package.json`
directly, and verify with a local production build — not just the dev server.

## NativeWind token cache

**A new design token added to the Tailwind preset does not take effect on
device until the NativeWind cache is cleared.** The class compiles into CSS
and passes lint, but the old cached output continues to ship. After adding a
token, run `rm -rf node_modules/.cache/nativewind .expo/cache` followed by
`expo start --clear`. Same family as "only breaks on device" — the symptom is
worse because the class appears to exist.
